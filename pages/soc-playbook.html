SOC Analyst Playbook

Every attack technique on the previous page maps to a detection, an investigation procedure, and a mitigation. This page is the response side of that equation — Sigma rules, YARA signatures, Sysmon config, and where each finding lands in Defender and Sentinel.

Alert Triage Workflow

graph LR A[Alert Fires
Sentinel / Defender / SIEM] --> B[Triage

host, account, timeframe] C --> D[Investigate
4624/4688/Sysmon/PowerShell logs] D --> E[Contain
isolate host, disable account, revoke tokens] E --> F[Eradicate
kill process, remove persistence] F --> G[Recover & Report
reset creds, rotate krbtgt if Golden Ticket]
BLUE TEAM NOTE
Scope before you contain. Isolating a single host in a lateral-movement chain just tells the attacker to pivot from a different one — pull the account's full logon history (4624/4648) across all hosts before you act.

Detection Matrix

One row per technique from the Attack Techniques page — what to watch, how to confirm, how to stop it.

TechniqueDetectionInvestigationMitigation
LSASS Dumping Sysmon EID 10 (ProcessAccess) targeting lsass.exe with GrantedAccess 0x1010/0x1410/0x1438; Defender ASR rule "Block credential stealing from LSASS." Identify the source process and its parent; check for comsvcs.dll rundll32 MiniDump invocation in 4688 command lines. Enable LSA Protection (RunAsPPL) and Credential Guard; restrict debug privilege.
Kerberoasting 4769 burst for many SPNs from one account, RC4 (0x17) encryption type, short time window. Pivot on the requesting account (TargetUserName); check whether that account normally accesses those SPNs. AES-only service accounts, gMSA/managed service accounts, long random passwords.
Golden Ticket 4768/4769 with anomalous encryption or an account that "logged on" without a corresponding 4624; ticket lifetime exceeding domain policy. Correlate the SID in the PAC against a disabled or nonexistent account — Golden Tickets can forge SIDs for accounts that no longer exist. Rotate the krbtgt password twice (back-to-back), monitor with Microsoft Defender for Identity.
Pass the Hash / NTLM Relay 4624 Logon Type 3 with NTLM, no matching interactive logon; 4776 spikes from a single relay source. Check LmPackageName/AuthenticationPackageName in 4624; correlate source IP against known workstation inventory. Disable NTLMv1, enable SMB/LDAP signing and Extended Protection for Authentication (EPA), restrict NTLM domain-wide via GPO.
Service Abuse 7045 (new service) with an unsigned or LOLBin binary path; 4697 for security-audited installs. Pull ImagePath from the event, check signature and prevalence; correlate with the installing account's 4688. Least-privilege service accounts, restrict who can write to HKLM\SYSTEM\CurrentControlSet\Services.
Registry Persistence Sysmon EID 13 (RegistryEvent) on Run/RunOnce, Winlogon Shell/Userinit, or IFEO Debugger values. Diff the value against a known-good baseline; check the writing process's parent chain. Application control (WDAC/AppLocker), restrict write ACLs on autostart keys.
Scheduled Task Abuse 4698 (task created) with a payload in <Actions>; Sysmon EID 1 for schtasks.exe/taskeng.exe children. Inspect the task XML for the command line and trigger; check "Run whether user is logged on or not" + SYSTEM context. Restrict SeCreateGlobalPrivilege, audit Task Scheduler operational log.
WMI Abuse Sysmon EID 19/20/21 (WmiEvent) for filter/consumer/binding creation; 4688 for wmic process call create. Enumerate __EventFilter/CommandLineEventConsumer in the WMI repository (OBJECTS.DATA). WMI namespace ACLs, disable remote WMI where unneeded, monitor with Sysmon WMI events.
PowerShell Abuse 4104 Script Block Logging capturing de-obfuscated content; suspicious -EncodedCommand/IEX/DownloadString patterns. Read the full de-obfuscated block from 4104, not just the 4688 command line (which is often truncated/obfuscated). Constrained Language Mode, AMSI, PowerShell v2 removal (no logging support), Script Block Logging enabled by GPO.
DLL Search Order Hijack Sysmon EID 7 (ImageLoad) for a DLL loading from an unexpected/writable directory; unsigned DLL with the name of a system DLL. Compare load path against the expected system directory; check file creation time vs. host binary. WDAC/AppLocker DLL rules, avoid running from user-writable directories, keep systems patched (many are fixed at the app level).
COM Hijacking Sysmon EID 13 on HKCU\Software\Classes\CLSID\{GUID}\InprocServer32. Resolve the CLSID to its legitimate component; check whether the new DLL path is expected. Monitor UsrClass.dat-backed CLSID keys, application allow-listing.

Sigma Rules

Sigma is a generic, SIEM-agnostic signature format — write once, convert (via sigma-cli/pySigma) to Sentinel KQL, Splunk SPL, or Elastic EQL.

sigma / lsass_access.yml YAML
title: Suspicious Access To LSASS Process
id: 0a1b2c3d-4e5f-6789-abcd-ef0123456789
status: stable
logsource:
  category: process_access
  product: windows
detection:
  selection:
    TargetImage|endswith: '\lsass.exe'
    GrantedAccess:
      - '0x1010'
      - '0x1410'
      - '0x1438'
      - '0x143a'
      - '0x1fffff'
  filter_known_tools:
    SourceImage|endswith:
      - '\MsMpEng.exe'
      - '\werfault.exe'
  condition: selection and not filter_known_tools
falsepositives:
  - Legitimate EDR/AV/crash-dump tooling
level: high
sigma / kerberoasting_burst.yml YAML
title: Possible Kerberoasting via RC4 TGS Requests
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4769
    TicketEncryptionType: '0x17'
  filter:
    ServiceName: 'krbtgt'
  timeframe: 5m
  condition: selection and not filter | count(ServiceName) by TargetUserName > 5
level: high

YARA Rules

YARA matches on file/memory content — useful for identifying known offensive tooling (Mimikatz, Rubeus) on disk or in a memory dump.

yara / mimikatz_strings.yar YARA
rule Mimikatz_Generic_Strings
{
    meta:
        description = "Detects common Mimikatz module/string artifacts"
        reference = "Public tooling signature - defensive use"
    strings:
        $s1 = "sekurlsa::logonpasswords" ascii wide
        $s2 = "kerberos::golden" ascii wide
        $s3 = "lsadump::dcsync" ascii wide
        $s4 = "privilege::debug" ascii wide
        $mz = { 4D 5A }
    condition:
        $mz at 0 and 2 of ($s1,$s2,$s3,$s4)
}

Platform Coverage

Sysmon

The visibility layer native Windows logging doesn't provide: full command lines with hashes (EID 1), network connections (3), image loads (7), process access (10), registry (13), WMI (19-21), pipes (17/18). Deploy with the SwiftOnSecurity-style baseline config and tune from there.

Microsoft Defender

Attack Surface Reduction (ASR) rules block whole technique classes pre-emptively (LSASS credential theft, Office child-process spawning). Defender for Endpoint's timeline correlates process, network, and file events per device automatically.

Microsoft Sentinel

Central KQL-driven SIEM/SOAR. Analytics rules (often Sigma-converted) fire incidents; playbooks (Logic Apps) can auto-isolate a host or disable an account. IdentityLogonEvents and SecurityEvent tables are the Kerberos/NTLM workhorses.

Sample Sentinel KQL Hunt

sentinel / kerberoasting-hunt.kql KQL
SecurityEvent
| where EventID == 4769
| where TicketEncryptionType == "0x17"
| where ServiceName != "krbtgt"
| summarize RequestCount = count(), Services = make_set(ServiceName)
    by TargetUserName, bin(TimeGenerated, 5m)
| where RequestCount > 5
| order by RequestCount desc
DID YOU KNOW?
A double krbtgt password reset is required to fully evict a Golden Ticket forger — resetting once still leaves the previous password (and any ticket signed with it, within its lifetime) valid, because AD keeps the last two passwords active for compatibility.
