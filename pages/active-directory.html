Active Directory

Active Directory is a distributed, replicated, hierarchical database of security principals. Kerberos is the authentication protocol; AD is the world it authenticates into — the source of truth for who exists and what they're allowed to do.

Domain

A security and administrative boundary — its own user/group database, its own Kerberos realm, its own KDCs. Each domain has at least one Domain Controller.

Forest

The true security boundary in AD — a set of domains sharing a common schema, configuration partition, and Global Catalog. Anything inside one forest can, in principle, be reached by a Forest/Enterprise Admin.

Tree

A set of domains in a forest that share a contiguous DNS namespace (e.g. corp.local and emea.corp.local). A forest can contain multiple trees with unrelated namespaces.

Organizational Unit (OU)

A container within a domain used to organize objects and scope Group Policy / delegated administration — not a security boundary; it's purely administrative.

Trust

A relationship letting principals in one domain/forest authenticate to resources in another — one-way or two-way, transitive or non-transitive. Trusts are also the path attackers use for cross-domain/cross-forest lateral movement.

Sites

A mapping of your physical/network topology (IP subnets) onto AD, used to keep authentication and replication traffic local to fast links instead of crossing slow WAN links unnecessarily.

Domain Controllers, KDC, LDAP, DNS

Domain Controller

A server hosting a writable (or read-only) copy of the AD database (ntds.dit) and running the NTDS, Netlogon, and KDC services.

LDAP

The protocol clients use to query and modify AD objects (port 389, or 636 for LDAPS). Nearly every AD-aware tool — from dsquery to BloodHound — talks LDAP under the hood.

DNS

AD is DNS-dependent by design — clients locate DCs and KDCs via SRV records (_ldap._tcp.dc._msdcs.corp.local). Broken DNS breaks Kerberos, since SPN resolution and KDC discovery both go through it.

Global Catalog

A partial, forest-wide searchable index of every object (port 3268/3269), letting a client find an object anywhere in the forest without knowing which domain it lives in.

Group Policy, SYSVOL & NETLOGON

Group Policy Objects (GPOs) are stored in two halves that must stay in sync: the GPC (Group Policy Container, an AD object holding version numbers and links) and the GPT (Group Policy Template, the actual files on disk under SYSVOL). Every DC replicates a full copy of SYSVOL, which is shared out as the \\domain\SYSVOL and \\domain\NETLOGON shares that every domain-joined machine reads at boot and logon (logon scripts live in NETLOGON).

PathPurpose
\\corp.local\SYSVOL\corp.local\PoliciesGPT files for every GPO — scripts, registry.pol, security templates.

Replication engineDFS-R (modern) or the legacy File Replication Service (FRS) keeps every DC's SYSVOL copy identical.

Replication & FSMO Roles

AD is a multi-master database — almost any DC can accept a write, then replicates it to the others. Five operations, though, can't safely be multi-master (they'd create irreconcilable conflicts), so exactly one DC in the relevant scope holds each as a FSMO role.

FSMO RoleScopeWhy it can't be multi-master
Schema MasterForest (1 per forest)Two simultaneous schema changes could produce an inconsistent object model forest-wide.
Domain Naming MasterForest (1 per forest)Prevents two domains from being added to the forest with the same name.
RID MasterDomain (1 per domain)Hands out blocks of RIDs to each DC so no two objects in the domain ever get the same SID.
PDC EmulatorDomain (1 per domain)Authoritative time source, password-change urgency master, and legacy PDC compatibility target.
Infrastructure MasterDomain (1 per domain)Keeps cross-domain object references (group membership across domains) up to date.
RODC — Read-Only Domain Controller
Holds a read-only copy of the AD database — no outbound password writes, and by default caches no user credentials at all until explicitly allowed via the Password Replication Policy. Designed for low-physical-security sites (branch offices) where a full writable DC would be too risky if the hardware were stolen.
DID YOU KNOW?
An OU is not a security boundary — an Enterprise/Domain Admin can always reach into any OU. Only the domain (and ultimately the forest) is a real security boundary in AD.
