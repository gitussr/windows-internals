Detection Foundations

Windows Event Logs

Every technique on the previous pages leaves a trace somewhere in these logs. Knowing the event IDs cold is what separates "I read about Kerberoasting" from "I can find it in a SIEM at 3am."

Log Sources

Security.evtx

The primary authentication/authorization/audit log — logon/logoff, object access, privilege use, account management. Requires an explicit audit policy (Local Security Policy or GPO) to populate most of the interesting IDs.

System.evtx

Driver/service/kernel-level events — service installs (7045), boot events, driver failures. Populated regardless of audit policy, which is exactly why 7045 lives here.

Application.evtx

Application-level errors, warnings, and info events — .NET crash dumps, MSI installer logs, application-specific auditing.

PowerShell Logs

Microsoft-Windows-PowerShell/Operational — Script Block Logging (4104) captures the full de-obfuscated script text; Module Logging (4103) records pipeline execution details. The single richest log source for fileless attack investigation.

Sysmon Logs

Microsoft-Windows-Sysmon/Operational — process creation with full command line and hashes (Event ID 1), network connections (3), process access (10, the LSASS-dumping detector), registry modification (13), and much more that native Windows logging doesn't provide out of the box.

Windows Defender Logs

Microsoft-Windows-Windows Defender/Operational — detections (1116/1117), Attack Surface Reduction rule blocks (1121), and Controlled Folder Access events, all correlatable with Sysmon/Security log entries for the same timestamp.

Event IDs Every Analyst Must Know

All from Security.evtx unless noted. Logon Type in 4624/4625/4776 tells you how — 2=Interactive, 3=Network, 4=Batch, 5=Service, 7=Unlock, 8=NetworkCleartext, 9=NewCredentials, 10=RemoteInteractive (RDP), 11=CachedInteractive.

Event IDNameWhat it means
4624Account logged onA logon succeeded. Check the Logon Type — a 4624 with Logon Type 3 (Network) from an unfamiliar host is classic lateral movement.
4625Account failed to log onA logon attempt failed. High volume from one source = brute force / password spray; check the Failure Reason substatus.
4648Logon attempted using explicit credentialsA process explicitly supplied different credentials than its own token (e.g. runas, net use /user:) — a strong lateral-movement / credential-testing signal.
4672Special privileges assigned to new logonThe new logon's token includes sensitive privileges (e.g. SeDebugPrivilege, SeTcbPrivilege) — effectively "an admin-equivalent account just logged on."
4688A new process has been createdProcess creation — with ProcessCommandLine auditing enabled, this is your process-tree backbone for investigation.
4697A service was installed (Security log)Same event as 7045 below, but logged to Security.evtx — requires the "Audit Security System Extension"/service-install audit subcategory enabled.
4698A scheduled task was createdIncludes the full task XML in the event — inspect the <Actions> block for the real payload.
4720A user account was createdNew local or domain account — correlate with who created it (SubjectUserName) and when, immediately after other suspicious activity.
4728Member added to a security-enabled global groupE.g. added to "Domain Admins" — one of the highest-signal privilege-escalation events in AD.
4732Member added to a security-enabled local groupE.g. added to the local "Administrators" group on a single machine.
4768A Kerberos TGT was requested (AS-REQ)Logged on the DC. The encryption type field flags weak crypto (RC4, 0x17); a flood of these from one source is an AS-REP Roasting or brute-force indicator.
4769A Kerberos service ticket was requested (TGS-REQ)Logged on the DC. A burst of these for many different SPNs from one account, especially with RC4 encryption, is the signature of Kerberoasting.
4771Kerberos pre-authentication failedSimilar to 4625 but Kerberos-specific — repeated failures against one account signal a targeted password guess or AS-REP roasting probe.
4776DC attempted to validate credentials (NTLM)Logged when NTLM (not Kerberos) is used to authenticate against a DC — useful for finding legacy NTLM usage and NTLM relay targets.
7045A service was installed (System log)Always logged, no audit policy required — the single most reliable native signal for new-service persistence, including PsExec-style lateral movement.
DID YOU KNOW?
Event ID 4769 is logged for every Kerberos service ticket request — including totally normal ones. Kerberoasting detection isn't "alert on 4769," it's "alert on an abnormal volume or pattern of 4769s using weak encryption."
