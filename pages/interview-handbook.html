1. Boot Process & Architecture

01Walk through what happens between pressing the power button and seeing the logon screen.
UEFI firmware runs POST, Secure Boot verifies and launches bootmgr, which reads the BCD and hands off to winload.efi. Winload loads ntoskrnl.exe, hal.dll, and boot-start drivers, then transfers control to the kernel. The kernel finishes initializing and starts smss.exe, which spawns csrss.exe and wininit.exe in Session 0; wininit.exe starts services.exe and lsass.exe. Winlogon starts in the interactive session and launches logonui.exe to render the credential UI. See Boot Process.
02What's the difference between BIOS/MBR boot and UEFI/GPT boot?
Legacy BIOS reads a 16-bit boot sector from the MBR with no signature verification and a 4-primary-partition limit. UEFI is a full pre-OS execution environment that reads the GPT partition table, executes signed EFI applications from the EFI System Partition, and supports Secure Boot — cryptographic verification of every boot component before it runs.
03How does Secure Boot actually stop a bootkit?
UEFI firmware holds a database of trusted signing certificates (db) and revoked ones (dbx). Before executing bootmgr, any boot loader, or a boot driver, firmware checks its digital signature against that database. An unsigned or tampered bootkit fails verification and the chain halts rather than executing malicious pre-OS code.
04What role does the TPM play beyond BitLocker?
The TPM performs Measured Boot — it hashes each stage of the boot chain into Platform Configuration Registers (PCRs) that can't be reset except by reboot. BitLocker seals its key to specific PCR values so the volume only unlocks if boot components are unmodified; the same measurements back Windows Hello key protection and remote attestation.
05What is the BCD and what replaced it?
Boot Configuration Data is a firmware-independent registry-format database (managed via bcdedit) describing boot applications, their load order, and settings. It replaced the plaintext boot.ini used through Windows XP, adding structure needed for multi-boot UEFI systems and features like Secure Boot policy and hypervisor launch settings.
06What does the HAL actually abstract, and why does it matter?
The Hardware Abstraction Layer (hal.dll) sits between ntoskrnl.exe and the hardware, abstracting interrupt controllers, DMA, timers, and bus access. It lets the same kernel binary run across different chipsets without hardware-specific kernel code, and is why kernel-mode drivers call HAL routines instead of touching hardware directly.
07What is smss.exe responsible for, and why can't you kill it?
The Session Manager Subsystem is the first user-mode process the kernel starts. It creates environment variables, processes pending file rename operations (PendingFileRenameOperations), initializes the paging file, and spawns csrss.exe and wininit.exe/winlogon.exe per session. It's not a normal killable process — terminating it triggers an immediate system bugcheck because the OS has no supervisor left for session creation.
08Why is Session 0 non-interactive since Windows Vista?
Pre-Vista, services ran in the same session as the interactive user, so a SYSTEM-level service rendering a window could be attacked from the user's desktop (the "shatter attack"). Session 0 Isolation moved all services into a dedicated, non-interactive session, so only session 1+ hosts the interactive logon and desktop, closing that privilege-escalation path.
09How has the logon architecture changed from Windows XP to Windows 11?
XP used GINA (Graphical Identification and Authentication), a single replaceable DLL for the whole logon UI — powerful but a huge attack surface. Vista replaced it with the Credential Provider model (COM-based, multiple providers can coexist), moved logon UI into its own process (logonui.exe), and added UAC. Windows 10/11 layered on Windows Hello (biometric/PIN backed by TPM-protected keys), Credential Guard, and passwordless push toward FIDO2/passkeys.
10What is the Secure Attention Sequence and why does Ctrl+Alt+Del matter?
Ctrl+Alt+Del is trapped directly by the kernel/Winlogon before any user-mode application — including malware — can intercept it, guaranteeing the resulting secure desktop and credential prompt are genuinely Winlogon's, not a spoofed login screen. It's the one keystroke combination no ordinary process can hook.

2. Windows Logon & Processes

11What's the division of labor between winlogon.exe and logonui.exe?
winlogon.exe owns the secure desktop, session lifecycle, and SAS handling but has no UI of its own; it launches logonui.exe to render the actual credential-entry screen and host credential provider tiles. Logonui exits once credentials are collected and passed back — this separation keeps the UI-rendering surface (larger attack surface) out of the trusted, privileged Winlogon process.
12What launches userinit.exe and what does it do?
Winlogon launches userinit.exe after successful authentication and profile load. Userinit runs logon scripts, processes the HKCU\...\Winlogon\Shell value (normally explorer.exe), starts the shell, and then exits — it never stays resident, which is exactly why hijacking its registry value is a classic persistence/defense-evasion trick (the malicious child has no obvious "userinit.exe" parent still running).
13What does csrss.exe do, and why is it critical?
The Client/Server Runtime Subsystem is the user-mode half of the Win32 subsystem — it handles console window management, process/thread creation and termination notifications, and shutdown coordination. It's marked critical: killing it bugchecks the system, same as smss.exe or wininit.exe, because too much of user-mode Windows depends on it being alive.
14Who starts services.exe and what does it manage?
wininit.exe starts services.exe, which hosts the Service Control Manager (SCM). The SCM reads service configuration from HKLM\SYSTEM\CurrentControlSet\Services, starts services in dependency order, and is the component sc.exe/net start talk to — also the source of Event ID 7045 whenever a new service is installed.
15What does dwm.exe do and why does it run per-session with elevated integrity?
The Desktop Window Manager composites all window surfaces into the final rendered desktop (enabling transparency, live thumbnails, and the modern shell visuals). It runs at a higher integrity level than normal apps because it has access to every window's rendered surface across the session — a compromise there is a broad information-disclosure risk.
16What is svchost.exe and why are there so many instances?
svchost.exe is a generic host for services implemented as DLLs rather than standalone EXEs. Each instance loads a group of services sharing a security context (defined by the -k parameter tying it to a registry service group), so a compromise or crash in one group doesn't necessarily take down unrelated services. Since Windows 10 1703+, most services run in their own svchost.exe given sufficient RAM, reducing blast radius further.
17What is taskhostw.exe and why does it appear in process trees so often?
It's a generic host process for DLL-based Scheduled Tasks (the task-scheduler analogue of svchost.exe). Because it's a legitimate, common, signed process, it's a favorite masquerading target for scheduled-task persistence — always verify the actual task action, not just the hosting process name.
18Why does explorer.exe run at Medium integrity even for an admin user?
UAC issues an administrator a filtered standard token by default; explorer.exe (the shell) launches with that filtered token at Medium integrity so ordinary desktop interaction doesn't run with full admin rights. Elevating (a UAC prompt) spins up a separate process with the full admin token — the shell itself never silently escalates.
19If lsass.exe crashes, what happens to the system?
Windows immediately bugchecks (blue screen) rather than continuing without an authentication authority — lsass.exe is a critical process, deliberately, because a system silently running with no functioning security subsystem is more dangerous than an abrupt, forced reboot.
20What DLLs does winlogon.exe depend on for interactive logon, at a high level?
credprov.dll-family credential provider COM objects supply the credential UI logic hosted by logonui.exe; Winlogon itself talks to lsasrv.dll (inside lsass.exe) over LPC/RPC to submit collected credentials for authentication, and to userenv.dll/profapi.dll for profile load once authentication succeeds.

3. LSASS & Credential Providers

21What exactly does LSASS own?
The Local Security Authority Subsystem Service enforces local security policy, manages authentication packages, generates access tokens on successful logon, and — critically for attackers — holds credential material (NTLM hashes, Kerberos keys/tickets, sometimes plaintext-equivalent secrets from legacy packages) in its process memory for SSO to work without re-prompting the user.
22What is a Credential Provider and what interface does it implement?
A COM in-process server implementing ICredentialProvider (and per-tile ICredentialProviderCredential), registered under HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Authentication\Credential Providers. LogonUI enumerates and instantiates all registered providers, each contributing one or more logon tiles (password, PIN, smart card, biometric).
23How does Windows Hello avoid sending a password over the network at all?
Windows Hello uses asymmetric key pairs generated and sealed by the TPM; the biometric/PIN only unlocks the local private key, which signs an authentication challenge. The private key never leaves the device and the PIN/biometric is never transmitted or centrally stored — a compromise of one device's Hello data doesn't yield a reusable network credential.
24What does RunAsPPL (LSA Protection) actually change at the kernel level?
It marks lsass.exe as a Protected Process (Light) at a defined signer level. The kernel then refuses OpenProcess handle requests for memory-read access rights from any process that isn't itself a PPL at an equal or higher protection level — blocking tools like a plain Mimikatz from acquiring a debug handle, even from an Administrator context.
25How is Credential Guard different from LSA Protection?
LSA Protection blocks handle access to the LSASS process but secrets still live in the same kernel's memory space in principle. Credential Guard uses Virtualization-Based Security to run a separate, isolated LSA instance (LSAIso) inside a VBS enclave with its own memory space, protected by the hypervisor — even a kernel-mode compromise of the main OS can't read secrets it never has direct access to.
26Why did wdigest.dll become a security liability?
WDigest (HTTP Digest authentication) historically required LSASS to retain the user's plaintext-equivalent password in memory to compute digest responses on demand. That cached secret was trivially extractable by tools like Mimikatz. Microsoft shipped UseLogonCredential=0 as the default (and a hotfix for older systems) to stop the caching.
27What's the standard technique for extracting credentials from LSASS memory, at a conceptual level?
Open a handle to lsass.exe with read access, then create a memory minidump (directly with MiniDumpWriteDump, or indirectly via a living-off-the-land binary like the comsvcs.dll MiniDump export through rundll32) and parse the dump offline with a credential-extraction tool. RunAsPPL and Credential Guard both target this exact handle-acquisition step.
28How does Windows support offline/cached logon when a DC is unreachable?
On successful domain logon, LSASS caches a salted, hashed (not reversible-plaintext) verifier under HKLM\SECURITY\Cache (default: last 10 logons, tunable via CachedLogonsCount). If the DC is unreachable, the cached verifier authenticates the user locally with reduced group-policy application until connectivity returns.
29What registry key controls which authentication packages LSASS loads?
HKLM\SYSTEM\CurrentControlSet\Control\Lsa\Authentication Packages (and Security Packages for SSPI providers) lists the DLLs — msv1_0, kerberos, negotiate, etc. — LSASS loads at startup.
30What's the practical difference between a Primary Token and an Impersonation Token?
A Primary Token is assigned to a process at creation and defines its default security context for everything it does. An Impersonation Token is adopted temporarily by a single thread — typically a service acting on behalf of a calling client — without altering the process's own primary token, and only for the duration/scope the impersonation level (Identify/Impersonate/Delegate) allows.

4. Authentication Packages & NTLM

31What is msv1_0.dll responsible for?
It's the NTLM authentication package — computes and verifies NTLM challenge-response exchanges, and for local (non-domain) logons, validates against the SAM database via samlib.dll. It's the fallback whenever Kerberos can't be used (no DNS resolution to a DC, target addressed by IP, workgroup-only environment).
32Describe the NTLM challenge-response handshake.
Client sends a NEGOTIATE message; server replies with a CHALLENGE containing a random nonce; client responds with a value computed from the nonce and its NTLM hash (never sending the password or hash itself over the wire). The server (or a DC it forwards to via Netlogon) recomputes the expected response and compares.
33Why is Pass the Hash possible with NTLM but not (as directly) with Kerberos passwords?
NTLM authentication only ever requires the hash — it's never combined with a nonce and re-derived from the plaintext, so possessing the hash alone is a complete credential. Kerberos typically requires the key to decrypt a KDC-issued encrypted structure with a timestamp, though Kerberos has its own hash-equivalent issue via Overpass-the-Hash/Pass-the-Key.
34What is Negotiate (negotiate.dll) and why does it exist?
It's the SPNEGO pseudo-package — the actual entry point most Windows apps call through SSPI. It automatically selects Kerberos when the target is resolvable via SPN/DNS and falls back to NTLM otherwise, so applications don't need protocol-specific logic.
35What does schannel.dll handle, and how does it relate to logon?
Secure Channel implements TLS/SSL and certificate-based (smart card / client-cert) authentication as an SSPI security package. It's the package invoked for smart-card logon and any Windows-native TLS mutual authentication, distinct from NTLM/Kerberos but plugged into the same SSPI framework LSASS exposes.
36What's the role of netlogon.dll?
It implements the Netlogon secure channel between a member machine and a Domain Controller — used to pass-through NTLM authentication to the DC for validation and to establish the machine account's own trust relationship with the domain. Netlogon vulnerabilities (e.g. Zerologon) directly attack this trust-establishment handshake.
37What is an NTLM Relay attack and why does signing stop it?
An attacker coerces or intercepts a victim's NTLM authentication attempt and forwards (relays) it, unmodified, to a different target server, authenticating as the victim without ever knowing the password or hash. SMB/LDAP signing requires each message to be cryptographically signed with a session key derived during the original handshake — a relayed session lacks the right key material to produce valid signatures on the new connection.
38What's the difference between NTLMv1 and NTLMv2, and why does it matter?
NTLMv1 uses a weaker DES-based response over a fixed-length challenge, is faster to crack, and is vulnerable to well-known downgrade and relay attacks. NTLMv2 adds a client-supplied nonce, timestamp, and target info into an HMAC-MD5-based response, making offline cracking and pure replay significantly harder. Modern hardening guidance disables NTLMv1 entirely via GPO.
39What does cryptdll.dll do within the authentication stack?
It provides low-level cryptographic primitives (hashing, DES operations historically) consumed by msv1_0.dll and other packages for computing NTLM responses and related hash operations — a support library rather than a package with its own SSPI entry.
40How would you detect legacy NTLM usage in an environment that should be Kerberos-only?
Enable NTLM auditing (Network security: Restrict NTLM: Audit NTLM authentication GPO) and watch Event ID 4776 (DC-side NTLM validation) plus 8004 audit events, which name the client and target — both flag hosts or apps still falling back to NTLM so they can be remediated before enforcing a block policy.

5. Kerberos

41Walk through the full Kerberos authentication flow from logon to service access.
Client sends an AS-REQ (pre-authenticated with a timestamp encrypted under the user's key) to the KDC's Authentication Service; the AS validates it and returns a TGT plus a session key. To reach a service, the client sends a TGS-REQ (presenting the TGT) to the Ticket Granting Service naming the target SPN; the TGS returns a Service Ticket encrypted with the service account's key. The client presents that Service Ticket directly to the application server, which decrypts it with its own key to authenticate the user — no further KDC contact needed.
42What is the PAC and why does it matter for authorization, not just authentication?
The Privilege Attribute Certificate is a Microsoft extension embedded in Kerberos tickets carrying the user's SID, group memberships, and privileges. Kerberos alone only proves identity; the PAC is what lets a target server build the user's access token and make authorization decisions without a separate directory lookup.
43What's an SPN and what happens if two accounts register the same one?
A Service Principal Name uniquely maps a service instance (e.g. MSSQLSvc/sql01.corp.local:1433) to the account that runs it, letting Kerberos issue a ticket encrypted with the correct key. Duplicate SPNs across two accounts break Kerberos authentication for that service entirely — the KDC can't determine which account's key to encrypt the ticket with, and clients typically fall back to NTLM or fail.
44Explain Kerberoasting end to end.
Any authenticated domain user can request a Service Ticket for any registered SPN — that's normal Kerberos behavior. If the SPN is tied to a user account (not a machine account) with a weak password, the attacker requests the ticket, takes it offline, and brute-forces/cracks the portion encrypted with the service account's password-derived key — no elevated privileges or interaction with the target service required at any point.
45Why is a Golden Ticket so much more dangerous than a Silver Ticket?
A Golden Ticket is forged with the domain's krbtgt hash — the key that signs every TGT in the domain — granting the ability to mint tickets for any user, with any group memberships, valid against any service in the domain, and with a lifetime set by the attacker. A Silver Ticket is forged with a single service or computer account's hash, so it only grants access to that one service, without ever contacting the KDC (which also means no 4769 is logged for its use).
46Why does resetting the krbtgt password once not fully remediate a Golden Ticket compromise?
Active Directory retains the previous krbtgt password hash for compatibility during the reset propagation window, so tickets signed with the old hash remain valid until it ages out. Incident response guidance is to reset it twice in succession (with replication settling between resets) to fully invalidate any forged tickets.
47What is AS-REP Roasting and how does it differ from Kerberoasting?
If an account has Kerberos pre-authentication disabled (DONT_REQ_PREAUTH), an attacker can request an AS-REP for it without knowing any credential; part of that reply is encrypted with the account's password-derived key and can be cracked offline — no valid ticket or authenticated session is needed at all, unlike Kerberoasting which requires an authenticated TGT first.
48What's the difference between Pass the Ticket and Pass the Hash?
Pass the Hash replays a captured NTLM hash to authenticate via NTLM. Pass the Ticket steals an actual Kerberos ticket (TGT or Service Ticket) — typically extracted from LSASS memory or a ticket cache file — and injects it into a different session/machine to impersonate its owner without ever touching a password or hash.
49Why is RC4 (etype 0x17) a red flag in Kerberos event logs today?
Modern domains default to AES; a client requesting/receiving RC4-encrypted tickets is either running on a legacy system or the SPN account has no AES keys configured (common for older/manually-created service accounts) — the second case is exactly the accounts most attractive to Kerberoast, since RC4's weaker key derivation cracks far faster than AES.
50How does a gMSA reduce Kerberoasting risk compared to a normal service account?
A Group Managed Service Account has AD automatically generate and rotate a 240-character random password on a schedule, with no human ever knowing or typing it. Even if its Service Ticket is Kerberoasted, the encrypted blob is effectively uncrackable in practice, and any successful crack is worthless shortly after the next automatic rotation.

6. Active Directory

51What's the relationship between a domain, a tree, and a forest?
A domain is a security and administrative boundary with its own database, policies, and trust relationships. A tree is a set of domains sharing a contiguous DNS namespace (e.g. corp.contoso.com under contoso.com). A forest is the true security boundary — one or more trees sharing a common schema, configuration partition, and Enterprise Admins group, linked by automatic two-way transitive trusts.
52What are the five FSMO roles and why can't AD be pure multi-master for everything?
Schema Master and Domain Naming Master (forest-wide, one each); RID Master, PDC Emulator, and Infrastructure Master (per-domain). Most AD writes are multi-master and replicate freely, but a handful of operations (issuing RID pools, schema changes, PDC-emulated password/lockout authority) would conflict irreconcilably if two DCs could perform them simultaneously, so a single DC holds authority for each.
53What's the difference between SYSVOL and the NETLOGON share?
SYSVOL (\\domain\SYSVOL) is the replicated folder holding Group Policy templates, scripts, and more; NETLOGON (\\domain\NETLOGON) is actually a share pointing at the SYSVOL\domain\scripts subfolder, historically used for logon scripts. Both are kept in sync across DCs via DFS-R (or the legacy FRS).
54What is a RODC and when would you deploy one?
A Read-Only Domain Controller holds a non-writable copy of the AD database and, by default, caches no credentials except those explicitly allowed by a Password Replication Policy. It's deployed at low-physical-security sites (branch offices) so a stolen RODC exposes only a limited, admin-defined credential set rather than the full domain database.
55How do AD Sites improve authentication and replication?
Sites map AD's logical structure to physical network topology (IP subnets with good connectivity grouped together). Clients preferentially authenticate against a DC in their own site (via DsGetDcName/DNS SRV records), avoiding slow WAN links, and intra-site replication runs frequently/uncompressed while inter-site replication is scheduled and compressed to conserve WAN bandwidth.
56What is DCSync and why is it dangerous even without ever logging into a DC?
DCSync abuses the legitimate Directory Replication Service (DRS) remote protocol — normally used by DCs to replicate with each other — to request password data (including krbtgt) for any account from a real DC, impersonating a replication partner. An account with Replicating Directory Changes/...All rights (often over-granted) can pull this remotely with no need to ever touch a DC's disk or console.
57What's the difference between an OU and a security group for applying policy?
An Organizational Unit is a container in the directory hierarchy that Group Policy Objects can be linked to directly, and it's the unit administrative rights are delegated over. Security groups are used within a GPO's security filtering or for granting resource access, but GPOs cannot be linked to a group the way they link to an OU, site, or domain.
58How does LDAP relate to Kerberos in a typical AD authentication + lookup flow?
Kerberos handles authentication (proving identity); LDAP is the directory access protocol used to query and modify AD objects (users, groups, computers) — often authenticated itself via Kerberos/SASL/GSSAPI rather than simple bind. A typical app flow: authenticate via Kerberos, then use the resulting security context to bind LDAP and query group memberships or attributes.
59What's a one-way vs. two-way, transitive vs. non-transitive trust?
Direction determines which domain's users can be authenticated by the other (a one-way trust from B to A lets A's users access B's resources, not vice versa). Transitivity determines whether the trust extends beyond the two directly configured domains — trusts within a forest are transitive automatically; external trusts to domains outside the forest are typically non-transitive by design, limiting blast radius.
60Why does DNS matter so much to AD, beyond name resolution?
AD relies on DNS SRV records (_ldap._tcp, _kerberos._tcp, etc.) for clients to locate DCs and KDCs dynamically — without correct DNS, Kerberos can't even find a KDC to send an AS-REQ to and silently falls back to NTLM. AD-integrated DNS zones also replicate through the same directory, tying DNS health directly to domain health.

7. Tokens, SIDs & Authorization

61Walk through what happens when a process tries to open a handle to a protected object.
The Object Manager routes the request to the Security Reference Monitor, which compares the requesting thread's effective access token (SIDs, group memberships, privileges, integrity level) against the object's Security Descriptor — first checking the integrity level against the object's mandatory label, then walking the DACL for an explicit Allow/Deny match. Any SACL entries matching the access are logged if auditing is enabled.
62What's the structure of a SID, and what does the RID tell you?
A SID is S-Revision-IdentifierAuthority-SubAuthority1-...-RID. Everything up to the last component identifies the issuing domain/machine; the final RID (Relative Identifier) is unique within that authority — well-known RIDs like 500 (built-in Administrator) and 512 (Domain Admins) are consistent across every domain, which is exactly what makes them useful (and abusable) targets.
63How does UAC's token splitting actually work?
On logon, an administrator gets two linked tokens: a filtered standard token (Administrators group marked deny-only, elevated privileges stripped) used for the everyday shell, and a full token with all rights intact. Launching something "as administrator" creates a new process using the full token via a consent/credential prompt — the two tokens are never merged into one running process.
64What's Mandatory Integrity Control and how is it different from the DACL?
MIC assigns every process/object an integrity level (Untrusted/Low/Medium/High/System) and enforces a simple rule independent of the DACL: a subject can't write to an object of higher integrity, regardless of what the DACL would otherwise allow. It's why a Low-integrity browser sandbox process can't write to your Medium-integrity Documents folder even though your user account's DACL permissions would normally allow it.
65What's the difference between a DACL and a SACL?
The Discretionary ACL determines who is allowed or denied specific access to an object — it's the actual access-control decision. The System ACL doesn't grant or deny anything; it defines which access attempts (successful, failed, or both) get written to the Security event log, independent of whether the DACL allowed the access.
66What makes SeDebugPrivilege so significant if an attacker's token has it?
It lets a process open a handle to (and read/write the memory of) any other process on the system regardless of the target's DACL/owner — including LSASS — bypassing the normal per-object permission check entirely. It's typically restricted to Administrators/SYSTEM precisely because it's a universal skeleton key for cross-process memory access.
67What's the difference between NTFS permissions and share permissions, and which wins?
NTFS permissions apply to the file/folder itself regardless of access path; share permissions apply only when accessing via that specific network share. When both apply (remote SMB access), the effective permission is the more restrictive intersection of the two — a share set to Full Control doesn't override a stricter NTFS ACL underneath it.
68Where does token creation actually happen during logon?
After the authentication package validates credentials and (for domain logons) the PAC is validated, LSASS builds the access token — assembling the user's SID, group SIDs, privileges, and default integrity level — and hands it back to Winlogon, which uses it to create the initial user process (ultimately userinit.exe/explorer.exe) as that token's owner.
69What's token theft/impersonation as a lateral-movement technique?
With SeImpersonatePrivilege or SeDebugPrivilege, an attacker already running code on a box can duplicate another logged-on user's (often a higher-privileged admin's) access token from an existing process and spawn a new process using it — effectively becoming that user for authorization purposes without ever knowing their password.
70What's the difference between authentication and authorization in the Windows model?
Authentication (handled by LSASS + authentication packages) answers "who are you" and produces a token. Authorization (handled by the Object Manager + Security Reference Monitor on every access attempt) answers "are you allowed to do this specific thing to this specific object," using that already-issued token against each object's security descriptor.

8. Registry & User Profiles

71What is NTUSER.DAT and when does it get loaded/unloaded?
It's the per-user registry hive file stored in the user's profile root, loaded as HKEY_CURRENT_USER at logon by the Profile Service (profsvc) and unloaded (flushed to disk) at logoff. It holds user-specific settings, preferences, and shell/application state that shouldn't apply system-wide.
72What's the difference between HKCU and HKLM, structurally?
HKLM is backed by machine-wide hive files (SYSTEM, SOFTWARE, SAM, SECURITY, DEFAULT) under %SystemRoot%\System32\config and applies to every user. HKCU is a per-user view — for the interactively logged-on user it's backed live by that user's NTUSER.DAT; it's actually a symbolic mapping under HKEY_USERS\{SID}.
73Name the five main registry hives and one thing each is known for.
SAM — local account hashes; SECURITY — LSA secrets and policy, readable only by SYSTEM; SYSTEM — services, drivers, boot config; SOFTWARE — installed applications and machine-wide settings; DEFAULT — the template hive copied to create a new user's NTUSER.DAT the first time they log on.
74What's the difference between Run and RunOnce keys?
...\Run entries execute every time the matching user (HKCU) or any user (HKLM) logs on, persistently. ...\RunOnce entries execute once and are then deleted by the OS — commonly used by installers for a single post-reboot continuation step, though attackers use it too for a lighter-footprint single-shot payload.
75How does the Winlogon Shell/Userinit hijack persistence technique work?
HKLM\...\Winlogon\Userinit normally holds C:\Windows\system32\userinit.exe, and Shell normally holds explorer.exe. Appending or replacing either value with an attacker binary makes it launch automatically for every interactive logon, inheriting the same trusted execution point as the legitimate shell startup.
76What is Image File Execution Options abuse?
HKLM\...\Image File Execution Options\{binary.exe}\Debugger is meant for attaching a debugger automatically when a named executable launches. Setting it to point at an attacker binary redirects execution of the named process to the attacker's payload instead — commonly abused against accessibility executables reachable from the pre-logon secure desktop (e.g. sethc.exe, the "sticky keys" backdoor).
77What's UsrClass.dat and why is it a favorite COM-hijacking target?
It's the per-user hive backing HKCU\Software\Classes, holding user-scoped COM/file-association registrations. Because it's per-user and writable without admin rights, attackers register or overwrite a CLSID's InprocServer32 there so any application instantiating that class quietly loads their DLL instead — persistence and defense evasion with zero elevation required.
78Besides Run keys and services, what other native mechanisms give attacker code automatic execution?
Scheduled Tasks (time or event-triggered, can run as SYSTEM), the per-user Startup folder (shell:startup), WMI Event Subscriptions (fire on a system event with no file on disk), and Winlogon's Shell/Userinit/Notify keys — each represents a different trigger model (time, event, logon, WMI event) but all achieve the same goal of unattended re-execution.
79Why does userenv.dll / profapi.dll matter for logon performance and reliability?
These implement the Profile Service — locating or creating the user's profile directory, loading/unloading NTUSER.DAT, applying Group Policy client-side extensions, and setting environment variables. A corrupt profile or a GPO client-side extension hanging here is one of the most common causes of a slow or "stuck" logon.
80How would you investigate a suspicious autostart entry found in a triage sweep?
Check the binary's signature and prevalence (unsigned + rare across your fleet is a strong signal), correlate the value's write time against Sysmon EID 13 to find the writing process and its parent chain, and check whether the account that wrote it had a legitimate reason to be modifying that key at that time.

9. Event Logs & Detection

81What's the difference between Event ID 4624 and 4625?
4624 is a successful logon; 4625 is a failed attempt. Both carry a Logon Type field (2=Interactive, 3=Network, 4=Batch, 5=Service, 7=Unlock, 8=NetworkCleartext, 9=NewCredentials, 10=RemoteInteractive/RDP, 11=CachedInteractive) that tells you the mechanism, which matters far more for triage than the ID alone.
82What does Event ID 4648 specifically flag, and why is it high-signal?
"Logon attempted using explicit credentials" — logged when a process explicitly supplies different credentials than its own token already has (runas, net use /user:, saved-credential RDP). Legitimate use exists, but a pattern of these from an unexpected source process is a strong lateral-movement / credential-testing indicator.
83Why is Event ID 7045 considered more reliable than 4697 for detecting new services?
7045 is written to System.evtx unconditionally, with no audit policy required. 4697 covers the same event but lives in Security.evtx and only populates if the "Audit Security System Extension" subcategory is explicitly enabled — an environment that hasn't tuned its audit policy will still catch new services via 7045 alone.
84What's the single richest log source for investigating fileless PowerShell attacks, and why?
Event ID 4104, PowerShell Script Block Logging. It captures the fully de-obfuscated script content at execution time — regardless of how heavily the attacker obfuscated the command line that launched it — because logging happens after PowerShell's own parser has already decoded/decompressed the payload.
85Why does a spike of 4769 events not automatically mean Kerberoasting?
Event ID 4769 fires for every Service Ticket request, including completely normal application usage. Kerberoasting detection has to be pattern-based — an abnormal volume of distinct-SPN requests from one account in a short window, combined with weak (RC4) encryption type — not a raw presence/absence signal.
86What does Sysmon Event ID 10 detect that native Windows logging doesn't?
ProcessAccess events — a process opening a handle to another process's memory, including the exact GrantedAccess mask. This is the primary telemetry for catching LSASS credential-dumping attempts (a handle open with read-memory rights against lsass.exe), which native Windows event logging doesn't surface at all.
87What's the significance of Event ID 4672?
"Special privileges assigned to new logon" — fires when a newly-created token includes sensitive privileges (SeDebugPrivilege, SeTcbPrivilege, etc.), effectively flagging "an admin-equivalent logon just happened." It's commonly correlated directly with the matching 4624 to confirm privileged-account activity.
88What does Event ID 4776 tell you that 4624 doesn't?
4776 is specifically the DC validating credentials over NTLM — its presence for an account/host that should be using Kerberos exclusively is itself a finding (legacy application, misconfiguration, or a downgrade/relay attempt), independent of whether the logon in 4624 ultimately succeeded.
89Why does Event ID 4698 (scheduled task created) require inspecting the task XML, not just the event summary?
The event includes the complete task definition XML, including the <Actions> block with the actual command/arguments that will run and the trigger/context ("run as SYSTEM," "run whether logged on or not"). The task name and description alone tell you almost nothing about whether the payload is malicious.
90How do you convert a detection idea into something deployable across different SIEMs?
Write it once as a Sigma rule — a YAML-based, platform-agnostic detection format with a logsource/detection structure — then use a converter (sigma-cli/pySigma backends) to generate Sentinel KQL, Splunk SPL, or Elastic EQL from the same source of truth, avoiding drift between platform-specific copies. See the SOC Playbook.

10. Attacks, Persistence & SOC Operations

91What's the difference between detection, investigation, and mitigation, and why does the order matter?
Detection is the alert firing on a signal (Sigma rule match, Sysmon event). Investigation scopes and confirms it (which host, which account, is it a true positive, how far did it spread). Mitigation closes the gap (contain, eradicate, harden). Acting on mitigation before investigation risks tipping off the attacker or containing the wrong host while the real foothold survives elsewhere.
92Why does DLL Search Order Hijacking still work against signed, trusted applications?
Windows resolves an unqualified DLL reference by searching a defined order — typically the application's own directory before system directories. Dropping a malicious DLL with the exact expected name earlier in that search path gets it loaded by the legitimate, often signed, host process, which is useful both for persistence and for evading security controls that only check the parent EXE's signature, not what it actually loaded.
93Why is WMI Event Subscription persistence so hard to find with standard triage checklists?
It lives entirely inside the WMI repository (OBJECTS.DATA) as an __EventFilter/CommandLineEventConsumer/__FilterToConsumerBinding triple — no file on disk, no Run key entry, no Scheduled Task, no new service. A responder checking only the "usual suspects" persistence locations will miss it entirely; Sysmon Event IDs 19-21 are the practical way to catch its creation.
94What's the intrusion chain from initial access to domain dominance, in order?
Initial Access (phishing, exposed service) → Execution (PowerShell/WMI) → Credential Access (LSASS dump, NTLM capture, Kerberoasting) → Persistence (Run keys, services, scheduled tasks, COM hijack) → Privilege Escalation (token theft, service misconfig) → Lateral Movement (Pass the Hash/Ticket, NTLM Relay) → Domain Dominance (Golden Ticket via krbtgt). See the Attack Techniques diagram.
95A host shows Sysmon EID 10 with GrantedAccess 0x1010 against lsass.exe from an unfamiliar process. What's your triage sequence?
Confirm it isn't a known AV/EDR/crash-dump tool (filter list); identify the source process's full path, signature, and parent chain via 4688/Sysmon EID 1; check whether a minidump file was written nearby; isolate the host if the process is unrecognized and unsigned; then assume credential compromise and rotate secrets for any account that had an interactive session on that box.
96Why do Sigma rules typically include a "filter" section alongside "selection"?
Raw selection criteria (e.g. "any process accessing LSASS with these rights") match legitimate tools too (AV engines, Windows Error Reporting). The filter section excludes known-good sources by path/hash so the rule's condition: selection and not filter only fires on the residual, unexplained matches — directly reducing false-positive volume for the analyst.
97What's the difference between what YARA and Sigma each detect?
YARA matches patterns (strings, byte sequences) inside files or memory — good for identifying known tooling like Mimikatz on disk or in a dump. Sigma matches structured log events (fields and values from EDR/Windows logs) — good for detecting behavior/activity patterns over time, like a Kerberoasting burst, regardless of which tool produced it.
98Why should you scope an incident across all hosts before isolating just one?
In a lateral-movement chain, isolating the first host you spot just signals the attacker to pivot from a different foothold you haven't found yet. Pulling the affected account's full logon history (4624/4648) across every host first reveals the true extent of the compromise, so containment can happen everywhere at once.
99What's the practical difference between Microsoft Defender and Microsoft Sentinel in a SOC workflow?
Defender for Endpoint is the EDR — it sits on the host, blocks technique classes proactively via ASR rules, and builds a per-device timeline. Sentinel is the SIEM/SOAR layer above it — ingesting Defender's signals alongside everything else (AD, network, cloud), running KQL analytics rules across the whole estate, and triggering automated playbooks (isolate host, disable account) when a rule fires.
100If you had to explain "defense in depth" for Windows logon security in one sentence, what would you say?
No single control is trusted alone — Secure Boot verifies the chain before the OS exists, TPM-sealed BitLocker protects data at rest, LSA Protection and Credential Guard isolate secrets in memory, Kerberos/NTLM hardening reduces what a stolen credential can do, tokens and MIC enforce authorization on every single access, and Sysmon/Sentinel/Defender assume all of the above will eventually be tested and catch what gets through.
INTERVIEW TIP
When an interviewer asks "how does Windows logon work," don't start with LSASS — start with power-on. Walking the full chain (UEFI → bootmgr → kernel → smss → Winlogon → LSASS → token → shell) in order, out loud, is the single strongest signal of real depth versus memorized trivia.
