Part 4 · Profiles & Persistence

Registry & User Profiles

The registry is where "who logged on" turns into "what their desktop looks like" — and it's also the single most common home for persistence, because so much of Windows' own startup behavior is registry-driven by design.

Registry Hives

HiveBacking fileContains
HKLM\SAM%SystemRoot%\System32\config\SAMLocal user accounts & hashes; ACL-locked even from local Administrators by default.
HKLM\SECURITY...\config\SECURITYLSA secrets, cached domain credentials, local security policy.
HKLM\SYSTEM...\config\SYSTEMServices, drivers, Control Sets, Session Manager settings — always readable, rarely writable by non-admins.
HKLM\SOFTWARE...\config\SOFTWAREInstalled software, machine-wide app configuration, Winlogon/IFEO keys.
HKLM\DEFAULT...\config\DEFAULTTemplate hive mounted as HKU\.DEFAULT — the basis for any brand-new user profile.
HKCU%USERPROFILE%\NTUSER.DATThe logged-on user's personal settings — mounted live at logon, unmounted (flushed to disk) at logoff.
HKCU\Software\Classes%USERPROFILE%\AppData\Local\Microsoft\Windows\UsrClass.datPer-user COM/shell registrations — a favorite target for COM hijacking because it's user-writable.

Environment Variables

Built by userenv.dll from system + user + Group Policy sources (HKLM\SYSTEM\...\Environment and HKCU\Environment) into the process environment block every child process inherits.

userinit.exe → explorer.exe

Userinit reads Winlogon!Userinit to know it's itself, then reads Winlogon!Shell to know what to launch (normally explorer.exe), then exits — it does not stay resident.

Shell Registry Keys & Autostart Locations

These are the highest-frequency persistence locations on Windows — largely because they're legitimate, documented startup mechanisms that malware simply reuses.

LocationBehavior
HKLM/HKCU\...\Winlogon!ShellWhat Winlogon launches as the shell — default explorer.exe.
HKLM\...\Winlogon!UserinitWhat runs before the shell — default userinit.exe, (trailing comma matters; extra entries after it all run).
HKLM/HKCU\Software\Microsoft\Windows\CurrentVersion\RunRuns every logon, indefinitely, for that hive's scope (machine-wide or per-user).
...\RunOnceRuns once, then the value is deleted — used legitimately by installers, abused for single-shot staged payloads.
Startup folder
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup		Anything here launches at logon — no registry edit needed at all.
Image File Execution Options
HKLM\...\IFEO\notepad.exe!Debugger		Silently redirects execution of the named binary to the "debugger" instead — a stealthy hijack, not just a startup hook.
Scheduled Tasks
C:\Windows\System32\Tasks		XML task definitions that can run as SYSTEM on a trigger (logon, time, event) — see Event ID 4698.
Services
HKLM\SYSTEM\CurrentControlSet\Services		Auto-start services run as SYSTEM before any user logs on at all — see Event ID 7045.

Persistence Mechanisms — Blue Team Summary

BLUE TEAM NOTE
None of the mechanisms above are inherently malicious — they're all legitimate OS features. Detection is about baseline deviation: know what Run keys, services, and scheduled tasks are supposed to exist on a given machine, and alert on anything new, unsigned, or pointing outside Program Files/System32.
DID YOU KNOW?
If Windows can't load a user's NTUSER.DAT (corruption, locked file, roaming profile server unreachable), it silently falls back to a temporary profile built from the DEFAULT hive — settings vanish on logoff, which is a classic "why did my settings reset?!" support ticket.
